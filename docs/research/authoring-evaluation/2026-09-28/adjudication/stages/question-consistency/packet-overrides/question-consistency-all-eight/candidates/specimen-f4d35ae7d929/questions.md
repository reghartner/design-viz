# Questions for the operator — kestrel-overnight

Reply "ok" to any question to accept my proposed default.

1. **How technical should the page be?**
   - Story: people, the porch, the camera, the phone and plain boxes such as "Kestrel cloud". No service names, API names or code on screen.
   - Mixed: the story plus the main Kestrel services by name, with plain captions.
   - Engineering: every service hop, API call, failure rule and code link.
   *Proposed default:* Story (business audience).

2. **When does the night start and end, and how should times look?**
   *Proposed default:* Thursday, Oct 1, 2026, from 10:00 PM (resident goes to bed) to about 9:30 AM Friday. 12-hour clock, short date ("Fri, Oct 2").
   Times I'd use (illustrative, chosen so the design's own battery numbers line up): raccoon about 12:40 AM, low-battery alert 2:00 AM, sunrise about 7:00 AM, courier about 9:10 AM.

3. **Who is the page for, and what is the one thing they should remember?**
   *Proposed default:* Product and support leads. Takeaway: "Even on a low battery overnight, the Porch Cam keeps recording, only alerts you when it matters, recharges itself from the sun, and still tells you about the package — late, but never lost — when home Wi-Fi drops."

4. **Which endings should the viewer be able to switch between?**
   *Proposed default:* two endings that share the night: (a) normal delivery — package alert arrives right away and the resident opens the clip; (b) Wi-Fi down at delivery — clip saved on the camera, Wi-Fi returns about 10 minutes later, the alert arrives late.

5. **In the Wi-Fi-down ending, does the resident open the clip after the late alert?**
   The design only says the resident opens the clip in the normal ending.
   *Proposed default:* No — that ending stops when the late alert arrives.

6. **Should the phone show the camera's page (battery %, sun-charging icon, "updated" time) at key moments, alongside the lock-screen alerts?**
   *Proposed default:* Yes — lock-screen alerts plus the Porch Cam's page in the app; and a separate "real battery" meter so viewers see the app's reported value can lag the camera's actual charge.

7. **Should the page show the raccoon clip on the app's timeline (saved, no alert)?**
   *Proposed default:* Yes — it shows the "animal, no alert" rule without waking the resident.
