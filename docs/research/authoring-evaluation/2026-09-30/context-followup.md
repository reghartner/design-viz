# Context and output follow-up

This follow-up uses retained public tool/usage metadata; it adds no author or grader outcome and changes no historical screen. Exact archive hashes are in [context-followup.json](context-followup.json).

In the four corrected-rebaseline runs, 82–86% of each eventual peak was already present in the request that produced the first specification write. Mean context there was 170,909.75 tokens, versus a mean peak of 204,662.25. This includes prior reading and ledger-writing work; it does not isolate their token contributions.

Within v1's own concurrent comparison, the focused arm's mean first-spec context was 35,300 tokens lower and its final peak was 33,114 tokens lower. Its visible mutation-input payload increased by 8,902.5 bytes and reported output by 5,741 tokens. The arm difference was already present before specification writing; an output-cost improvement was not demonstrated. V2's corresponding first-spec and peak differences were smaller: −16,431 and −10,828 tokens.

Public invocation usage reports 153,040 thinking tokens out of 324,892 output tokens in the corrected rebaseline (47.10%). All 40 phase records across rebaseline, v1 and v2 expose numeric thinking/output counters, and their resumed-session cumulative checkpoints reconcile with invocation sums. This does not identify the share spent on file payloads: mutation payloads are measured in bytes, and output minus thinking includes more than file writes. No reasoning content was inspected.

The v2 presentation audit does not support a skipped-reference explanation. Every v2 author read the same five changed reference files before the first specification write; their larger treatment versions account for 3,397 additional bytes. The strongest remaining hypothesis is changed cue timing and emphasis during panel selection: semantic card/log examples and reduced guide-path visibility lacked a corresponding composition cue. Shared renderer clipping and absent viewport feedback may amplify problems, but do not explain treatment assignment. Causality remains unproven.

## Consequences for the next tests

- Keep context, output tokens, visible mutation bytes and elapsed time separate. Record context at first editable write as well as peak, so later reading cannot masquerade as removed reading.
- Test a concise Workbench command contract separately from initial authoring. Its mandatory helper source is about 49 KB; the initial-authoring runs read a different helper of only 6.9 KB.
- For an initial-authoring reading manifest, vary routing and order while preserving presentation content and guide pointers. Place existing presentation pointers before panel selection. Any new composition rule is a separate intervention.
- Preserve v1 as a candidate for prospective confirmation; do not turn its missed historical threshold into a pass. File splitting and declaration-only payloads still need representative larger-spec evidence.

Every new experiment or revision starts with one representative unscored trial of the actual agent flow. Inspect it before expanding authors. Include matching Copy/Work-with-agent guidance in product changes, preserve failed attempts, and inspect one blinded reviewer's transport/schema/arithmetic before expanding grading. Infrastructure repairs require fresh frozen inputs; a working workflow alone is not evidence of quality or context savings.

## Contemporary exact-v1 cohort (added 2026-10-01)

This section was added after the registered contemporary cohort finished. The sections above and [context-followup.json](context-followup.json) are unchanged. Results, screen status and evidence bindings are in [v1-replication-results.md](v1-replication-results.md).

**Results.** Focused-v1's mean peak context was 10.5187% below control: 195,774.5 versus 218,788.25 tokens. That misses the 20% screen. The final source audit also triggered the repeated new correctness-defect guard, with three symptom families each found in two or more focused outputs and no control. The worst was a missing visible matching still for the opened clip, corrected to 3 focused / 0 control. The strategy does not qualify. Both quality arm differences remain null because one control grade is invalid. The source audit does not rescore anything or fill in the missing values. No strategy is promoted. This estimate is not pooled with the historical 14.49%.

**Where the difference arises.** Most of the peak gap was already present at the first spec Write. Mean first-spec context was 164,192 tokens for focused versus 184,209.25 for control, a gap of 20,017.25 of the 23,013.75-token peak gap. Before that Write, focused read fewer guidance bytes but more bytes from its own generated widget reports. All eight authors' metrics matched 64 of 64 public-usage crosschecks. Neither the thinking counters nor the mutation bytes measure file-payload tokens.

**Rejected helper proposal.** Fable (observed `claude-fable-5-1`) proposed making a compact helper index the default output, with details available through `--section`. An independent SOL feasibility check of the frozen helper source rejected that proposal as stated:

- `--catalog` already provides a 31-panel index (7,351 B) with type, name, use, what the panel shows, and file+anchor.
- `--guide` provides details for selected panels.
- `--section` supplies non-panel contract headings and rejects panels.

Every focused author read two different report generations, one from `--guide` and one from `--section`. No author repeatedly read the same report. A source/emitted overlap audit found no meaningful duplication to trim. Higher aggregate bytes alone do not justify a helper change or trial. This is recorded as negative evidence.

**Broader guidance inventory.** All 141 pre-write guidance Reads were inventoried. None was an identical-range reread within one author's context. The exact whole-response byte repeats all occur across authors, so they represent no saving inside any single author's context. Two requested ranges overlapped, but overlapping requests do not prove that redundant bytes were delivered. No trim proposal is justified.

**Defect cause.** The cause of the missing-clip family is not established. The relevant rules are byte-equivalent in the two kits. Readers of the camera-events guide include both focused and control authors. Focused run-02 included a Screen and passed, and controls run-03 and run-04 passed without reading that guide. No further context cut is selected from the higher byte counts.

**Selected conditional repair.** After the final Fable consult, the root coordinator selected one conditional quality-repair candidate. It is a small cue in the existing catalog/guide output, with matching agent guidance, for a visible matching Screen at the invoked clip opening, including inherited visibility and state. Details and constraints are in [v1-replication-results.md](v1-replication-results.md). The cue covers only the missing-clip family and cannot clear the guard. It is not implemented or trialed, and it carries no context claim. In the same session, Fable withdrew its bytes-to-tokens estimate and the inferences built on it. The existing limit on attributing tokens to individual components stands, and no further pass over the same counters will try to allocate file tokens.

**Operator guidance for any further experiment or revision:**

- Run one inspected author trial of the actual flow before expanding authors.
- Run one actual grader pilot that checks transport, schema and arithmetic before the grading fanout.
- Freeze inputs. Retain failures. Never retry or replace a grade for quality reasons.
- Before proposing cuts, inspect the actual helper modes and source, and inspect which report generations were actually read.
- A field appearing in authored output does not prove that the guidance describing it was necessary.
- File bytes are not tokens.
- Do not pool historical and contemporary deltas.
- When auditing source defects, check inherited panel visibility and content, and apply the frozen rule in the same way to both arms. A matching still can remain from an earlier step; the rule does not require a "Playing" label.
- Keep grades and diagnostic audits separate. Retain both the original and the revised audit reports.
- For a cue candidate, add no new required helper calls, modes or reports. Retain and assess incidental extra-call variation; do not automatically blame it on the treatment.
- Any product change must include file+key guidance for Copy for agent and Work with agent, plus tests of the actual flow, before adoption.
