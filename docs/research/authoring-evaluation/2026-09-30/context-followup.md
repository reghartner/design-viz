# Context and output follow-up

This follow-up uses retained public tool/usage metadata; it adds no author or grader outcome and changes no historical screen. Exact archive hashes are in [context-followup.json](context-followup.json).

In the four corrected-rebaseline runs, 82–86% of each eventual peak was already present in the request that produced the first specification write. Mean context there was 170,909.75 tokens, versus a mean peak of 204,662.25. This includes prior reading and ledger-writing work; it does not isolate their token contributions.

Within v1's own concurrent comparison, the focused arm's mean first-spec context was 35,300 tokens lower and its final peak was 33,114 tokens lower. Its visible mutation-input payload increased by 8,902.5 bytes and reported output by 5,741 tokens. The arm difference was already present before specification writing; an output-cost improvement was not demonstrated. V2's corresponding first-spec and peak differences were smaller: −16,431 and −10,828 tokens.

Public invocation usage reports 153,040 thinking tokens out of 324,892 output tokens in the corrected rebaseline (47.10%). All 40 phase records across rebaseline, v1 and v2 expose numeric thinking/output counters, and their resumed-session cumulative checkpoints reconcile with invocation sums. This does not identify the share spent on file payloads: mutation payloads are measured in bytes, and output minus thinking includes more than file writes. No reasoning content was inspected.

The v2 presentation audit does not support a skipped-reference explanation. Every v2 author read the same five changed reference files before the first specification write; their larger treatment versions account for 3,397 additional bytes. The strongest remaining hypothesis is changed cue timing and emphasis during panel selection: semantic card/log examples and reduced guide-path visibility lacked a corresponding composition cue. Shared renderer clipping and absent viewport feedback may amplify problems, but do not explain treatment assignment. Causality remains unproven.

## Consequences for the next tests

- Keep context, output tokens, visible mutation bytes and elapsed time separate. Record context at first editable write as well as peak, so later reading cannot masquerade as removed reading.
- Test a concise Workbench command contract separately from initial authoring. Its mandatory helper source is about 49 KB; the initial-authoring runs read a different helper of only 6.9 KB.
- For an initial-authoring reading manifest, vary routing and order while preserving presentation content and guide pointers. Place existing presentation pointers before panel selection. Any new composition rule is a separate intervention.
- Preserve v1 as a candidate for prospective confirmation; do not turn its missed historical threshold into a pass. File splitting and declaration-only payloads still need representative larger-spec evidence.

Every new experiment or revision starts with one representative unscored trial of the actual agent flow. Inspect it before expanding authors. Include matching Copy/Work-with-agent guidance in product changes, preserve failed attempts, and inspect one blinded reviewer's transport/schema/arithmetic before expanding grading. Infrastructure repairs require fresh frozen inputs; a working workflow alone is not evidence of quality or context savings.
